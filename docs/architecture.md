# Architecture

An overview of the code structure. Every ticket that changes the structure updates this file.

## Packages
- `korrektor`: the app: the entry point (`Main.kt`), the state, the screens and app logic. The UI is Compose with Material 3 (T011).
  - `AppModel.kt`: the state of the app as plain Kotlin with Compose state: the open `Project?`, its `metadata` (mirrored as state, because `Project.metadata` is plain data and the UI cannot observe it), which dialogs are open and the error to show. `windowTitle` and `displayTitle` give the title from the metadata, or the folder name for a project without metadata.
  - `App.kt`: the whole window: error banner, the start screen or the open project, and the two dialogs while they are open. `StartScreen.kt` (start page and `ErrorBanner`) and `ProjectScreen.kt` (the open project, with `ProjectActions` for what its buttons do) are stateless. While a project is open the whole window sits under the one key handler (`Modifier.shortcutKeys`), and the list of shortcuts is a third dialog (`AppModel.shortcutsOpen`).
  - `Shortcuts.kt`: the single table of the keyboard shortcuts (S06): `AppAction`, `Shortcut` (label, description, key combinations; the first one is shown) and `Shortcuts.resolve(event)`, which accepts a key going down with exactly the modifiers of a combination (Alt and Meta never, so that AltGr, which is Ctrl+Alt on Windows, cannot trigger one; Shift only where the table says so). The key handler, the menus and the list on F1 are all made from it. `Modifier.shortcutKeys(KeyActions)` is the handler: it works in the preview phase, above everything, so a shortcut is used up before the focused row, the page field or a button sees it. It only works if some element has the focus, which is why the text panel takes the focus at every page change. Enter, Backspace and Delete are not shortcuts but the keys of a line (`Shortcuts.editorKeys` lists them for the F1 list).
  - `ProjectKeys.kt`: what the shortcuts do in the open project (`KeyActions`): a table from `AppAction` to the call of the editor (`moveLine`, `firstLine`, `lastLine`) or the viewer (`goTo`, `zoomIn`, `zoomOut`, `fitPage`, `fitWidth`, `focusPageField`), plus `goToPage` and `leavePageField` for the page field. A page change by the keyboard tells the editor first where the cursor should go on arrival (`arriveAt`). A test checks that every action of the table has a handler.
  - `AppModel` also holds the right to work on the open project: `format/ProjectLock.kt` takes an operating system lock on `<project>/.lock` when a project is opened or created (only for a folder that has a `project.json`, so no lock file is left in just any folder) and gives it back when another project is opened. A second window or instance gets "already open"; a lock file left by a crash blocks nothing, since the system released the lock with the process.
  - `ProjectClosing.kt`: what happens when a project ends (S07). `requestClose` saves with `AutoSaver.saveNow` and then calls `AppModel.exit`; if saving fails it sets `closeProblem`, which shows `SaveFailedDialog` (close without saving, keep the app open, or `saveElsewhere`: `Project.copyTo` the whole project into a folder the user chose, write the unsaved pages into the copy, open the copy). `flushBeforeSwitch` saves before another project is opened, `closeProject` gives the lock back. `format/ProjectCopy.kt` has `Project.copyTo`.
  - `Menus.kt`: the menus *Go*, *View* and *Help* as plain data (`menus(MenuState)`), made from the table of shortcuts; each entry shows its key, and the entries only display it (the key handler does the work, so nothing is handled twice). `Main` turns them into a `MenuBar`. `ShortcutList.kt`: the list of all shortcuts and the keys of a line, opened with F1 (a dialog; F1, Escape and "Close" close it).
  - `NewProjectModel.kt` and `NewProjectDialog.kt`: the "New project" dialog. The model holds the fields and the rules (suggest title and location, `canCreate`, the folder that will be created), starts the creation on a background dispatcher while `busy` is set, shows the progress of the import (`importedPages`, `totalPages`) and has `cancel()`. On success `AppModel.openCreated` makes the project the open one, with a notice if pages had no text. The dialog is stateless apart from the model.
  - `ProjectCreation.kt`: `createProject` makes the project and imports its text, off the UI thread, and returns how it went (`Done`, `Cancelled`, `Failed`). On anything but success the project that was just made is deleted (`NewProject.discard`), also when cancelled, so no half-made project is left behind.
  - `LayoutState.kt` and `SplitPane.kt`: the window of an open project is the scan on the left and the text on the right with a divider (8 dp, resize cursor, a different colour on hover) that can be dragged. `LayoutState` holds the divider's position, the fraction of the width that the scan gets (0.2 to 0.8, 0.55 at the start), the same for every project, and saves it to the app settings when a drag ends (four decimals). `ProjectScreen` is a compact header (title and buttons in a row, metadata, pages and folder in a line) and a content slot.
  - `ViewPersistence.kt`: `AppModel.saveView()` (writes the open project's page and zoom to the settings now) and `keepViewSaved()` (saves them one second after the last change, nothing for a project that was only opened). `AppModel` makes the `ViewerState` of a project when it is opened, from what the settings remember, and saves the old project's view when another is opened; `Main` saves it when the window closes.
  - `ProjectFactory.kt`: the two steps (create the project folder, import the text) behind an interface; `DefaultProjectFactory` is the real one, tests and UI tests substitute slow or failing ones through `AppModel(projectFactory)`.
  - `KorrektorTheme.kt`: the colours of the app (brown, mustard and yellow on cream) and the Material 3 theme that uses them.
  - `MetadataForm.kt`: the four metadata fields (title, author, year, source) as an interface plus the shared field composable `MetadataFields`, used by both dialogs.
  - `EditMetadataModel.kt` and `EditMetadataDialog.kt`: the "Edit metadata" dialog for the open project. The model starts from the current values, enables saving only for a non-blank title and a change, keeps unknown metadata fields, and saves through `AppModel.updateMetadata`; if writing fails, the old metadata stays and an error is shown.
  - `PdfPicker.kt`: the interface for choosing a PDF, and `AwtPdfPicker` (the system file dialog). Tests replace it.
  - `FolderPicker.kt`: the interface for choosing a folder, and `SwingFolderPicker` (a `JFileChooser` in folder mode, because the AWT dialog cannot choose folders on Windows). Tests replace it.
  - `NewProject.kt`: the logic behind "New project": suggests a title from the PDF's file name, makes a safe folder name (`<title>.korrektur`), checks the PDF (a file with `%PDF-` near its start; pages are read at import, S03) and the target, and creates the project through `Project.create`.
- `korrektor.settings`: the settings of the app, as opposed to those of a project (T032).
  - `AppSettings.kt`: one JSON file in the user's config folder (`%APPDATA%\korrektor\settings.json`, `~/Library/Application Support/korrektor`, `$XDG_CONFIG_HOME` or `~/.config/korrektor`) with the last page and zoom of each project, keyed by the project folder's path: `{"version": 1, "projects": {"<folder>": {"page": 12, "zoom": {"mode": "fixed", "scale": 1.5}}}}`. Written with `AtomicFile`, at most 200 projects (the least recently used go first), fields it does not know are kept. Besides the views it has a top-level `"ui": {"split": 0.55}` with the position of the divider (T040). A damaged file or one from a newer version is moved aside as `settings.json.bad`; a failed write goes to stderr. Never part of a project. `SettingsJson.kt` is its reading and writing of JSON, `SettingsFile.kt` the file itself (reading, setting aside, atomic writing).
- `korrektor.editor`: correcting the text (S05).
  - `PageEdits.kt`: the edits of a page as pure functions on an immutable `PageLayer`: `setLineText`, `splitLine`, `joinWithPrevious`, `joinWithNext`, `addLineAfter`, `deleteLine`, and `readingOrder`. Each returns an `EditResult` (the new layer, and a `Focus`: where the cursor goes afterwards); a function that changes nothing returns the same layer. The text of a line is its words joined by one space, so a text is stored as `split(' ')` (two spaces make an empty word) and nothing is trimmed (V1). A word keeps its box if the line keeps its number of words; a cut word loses it; a line keeps its box unless the union of its words' boxes can be computed. `PageEditsSupport.kt` holds the helpers (words, boxes, ids).
  - `TextPanel.kt`: the text of the page shown: one row per line in reading order (`BookEditor.lines`) with the line number on the left and the text in the font of `HistoricFonts`, no wrapping. **Each row is a text field**: what the user types goes to `BookEditor.setLineText` at once, as typed (no normalization, no trimming; a pasted line break becomes a space). The cursor and the selection belong to the row, the text to the editor: if the editor's text for the line differs from the field's (a join, a split, later an undo), the field follows it. The row with the focus is the active line; a `FocusRequest` of the editor puts the cursor at a place (the row carries it out when it is composed, after the list has scrolled there). Enter in a row splits the line at the cursor (a selection is replaced by the break), Backspace at the start joins the line with the previous one, Delete at the end joins the next one into it (`lineKey`; the keys with Ctrl, Alt or Meta are left to the field); two buttons above the list, "Add line" and "Delete line", do the same for the mouse. A line without a box gets a dot (`no box <id>`) in the number column. A row has the test tag `line row <id>` (and the `selected` state when active) and its field `line text <id>`; the rows do not recompose when their line did not change. While the page is read the panel says "Loading…", if it cannot be read why, for a page without lines its note. Backspace at the start of an **empty** line deletes it instead of joining. The panel itself is focusable and takes the focus whenever the page changes or the page has no lines, until a row asks for it (the cursor arriving): a key only reaches the shortcuts if something has the focus.
  - `HistoricFonts.kt`: the font family of the text panel, Junicode (bundled in `src/main/resources/fonts/`, SIL OFL, see `docs/third-party.md`), and `hasGlyph` to ask whether the font itself has a character. Characters it lacks (OCR noise from other scripts) are drawn from a system font by the text engine.
  - `BookEditor.kt`: the corrected text of the open project in memory, shared by the scan and the text panel. It shows one page (`show`, which reads the page file on the IO dispatcher unless the page was changed in this session), offers the edits of `PageEdits` on that page (`setLineText`, `splitLine`, `joinWithPrevious`, `joinWithNext`, `addLineAfter`, `deleteLine`), and keeps every changed page in memory (`changedPages`) so that going away and back loses nothing. It also holds the active line and the latest `FocusRequest` (where the cursor should go: after a split, a join, a click on the scan). It writes nothing: autosave (S07) will write `changedPages`. `AppModel` makes one per open project and `App` calls `show` whenever the viewer's page changes, so both panels show the same page. For the keyboard it also knows the column of the cursor (`caret`, reported by the rows) and, for a page that is about to be opened by Up/Down/Ctrl+Up/Ctrl+Down, where the cursor goes on arrival (`arriving`, set by `arriveAt`, carried out by `applyArrival` when the page's lines are there; it belongs to its page and is used once). `LineNavigation.kt` has the moves as extensions: `moveLine(delta)` (answers `MOVED`, `NEXT_PAGE`, `PREVIOUS_PAGE` or `NOTHING`; the caller changes the page, as the editor does not know the book), `firstLine`, `lastLine`, `arriveAt`.
- `korrektor.viewer`: showing the scan of a page (S04).
  - `PageSource.kt`: the interface the viewer gets its pictures from (`size(page)`, `nativeScale(page)`, `render(page, scale, region)` with a `PixelRegion`; all suspending, pages from 1; and `caches`, which says whether the source remembers pictures), and `PageSourceFactory`. Tests put a fake in its place.
  - `PdfPageSource.kt`: the real source: PDFium on a thread of its own, so the UI thread never waits for a render; the PDF is opened on the first request, a page is loaded for each request and closed again, and `close()` closes the PDF. `DefaultPageSourceFactory` makes it wrapped in a `PageCache`.
  - `PageCache.kt`: a `PageSource` that remembers the pictures of another one by page, scale and region, within a budget in bytes (256 MB by default, 4 bytes per pixel): the least recently used go first, a picture larger than the budget is not kept. Sizes and scan resolutions of pages are kept for good. The lock is not held while rendering. It says `caches = true`, which makes the viewer render the neighbours of the page in advance.
  - `ViewerState.kt`: what the viewer shows: the current page (1 to the page count), the zoom mode (fit width, fit page, fixed), the scale, the zoom steps (25 % to 3200 % of actual size, 96 dpi, with the scan's own resolution, `PageSource.nativeScale`, as an extra stop between two of them), the limits (3200 %, whatever the scan; a floor of a tenth of the fit-page scale) and the position in the page. Plain Kotlin on Compose state. A page smaller than the viewport is centred and cannot be moved in that direction. Changing the page forgets the old page's size and position (so nothing is drawn with the wrong size) and keeps the zoom mode: a fit mode follows the new page once `setPage` has its size, a fixed scale stays.
  - `ViewerActions.kt`: what the user does with a `ViewerState`: fit width and fit page, previous, next and `pageOf` (a typed number: only whole numbers from 1 to the page count are pages), `zoomBy`, and `wheel` (Ctrl zooms; otherwise it scrolls by the delta of Compose, which gives Shift+wheel, a tilt wheel and a touchpad swipe as a sideways delta).
  - Also in `ViewerActions.kt`: `reveal(box)` scrolls the least that brings a box (page points) fully into the viewport, with a margin of a fifth of the viewport on the side it came from; a box already in view changes nothing, a box larger than the viewport is aligned at its top left, and in a direction in which the page is smaller than the viewport nothing moves. `App` calls it when the active line (its highlight) changes.
  - `PictureRequests.kt`: `nextRequest` says which picture to ask for: the whole page if it has at most 16 million pixels at the current scale (so scrolling at fit width or fit page never waits), otherwise the visible part plus a margin of one viewport on every side; nothing new while the last request still covers what is visible; `ViewerScrollbarAdapter` connects the scrollbars to the position. `ViewerGeometry.kt`: the arithmetic for the page's position.
  - `SavedView.kt`: what is remembered of a view (`SavedView`, `SavedZoom`), `ViewerState.saved()` and `restore()` (a page beyond the book becomes the last page; a fixed scale can be restored before the window and page are known). `ProjectViewer.kt`: the viewer of an open project with its `PageSource`, made when it appears and closed when it goes away.
  - `WordBoxes.kt`: the boxes of a page's text (`PageBoxes`, from a `PageBoxSource`) and where they are on the screen: `ViewerState.toScreen` is the transform of the picture (a point of the page lies at `origin + point × scale`; the format and the viewer both measure from the top left of the visible page), `visibleBoxes` keeps those in the viewport. `BoxOverlay.kt` draws them (a thin outline for each word, a stronger one for each line) when `ViewerState.showWordBoxes` is on, and reads the page's boxes in the background when it is switched on. `ProjectViewer` gives it the boxes of the project's **original** OCR layer (`readOriginalPage`), which never changes: an edited line has no word boxes, and the overlay must not change while the user types.
  - `LineHighlight.kt`: the line to mark on the scan (`LineHighlight`: id and box) and its overlay: a translucent yellow fill with an amber outline, drawn with the same transform as the picture (`ViewerState.toScreen`), above the picture and below the outlines of the word boxes. `PageViewer` takes a `highlight`; `ProjectViewer` passes it on. The editor decides what is marked (`korrektor.editor.highlightFor`): the box of the active line, but nothing for a line without a box, none if nothing is active, and none while the editor is not yet on the viewer's page.
  - `ScanLinks.kt`: how the scan and the text are linked: the `LineHighlight` to draw and what a click on the scan does (`onClick(PagePoint)`). A click is a tap that did not become a drag (dragging pans); `ViewerState.pagePointAt` turns the position into a point of the page in points (the inverse of `toScreen`, in `WordBoxes.kt`). `korrektor.editor.LineHits.kt` finds the line (`lineAt`: the smallest box containing the point, the first of equals, never a line without a box), guesses the character (`cursorIndexAt`) and `BookEditor.clickOnScan` makes the line active and asks for the cursor there. It also says what the page field does with a page typed (`onGoToPage`, so that the cursor goes to the page's first line) and with Escape (`onLeavePageField`).
  - `PageViewer.kt`: the composable: a toolbar that wraps onto a second line in a narrow panel (previous and next page, "Page n of N", a field to go to a page, fit width, fit page, −, +, the percentage, the "Word boxes" chip) and the page. The page is drawn from pictures of exactly the visible part at the current scale, one image pixel per screen pixel (a new request cancels the old one; while it renders, the old picture stays, stretched to the new scale; the area behind the page is the surface variant colour). Dragging with the mouse pans (hand cursor when the page can be moved), and scrollbars show in the directions where the page is larger than the viewport. It shows "Loading…", the picture or the reason it failed. Once a page has its picture and the source has a cache, the next and the previous page are rendered in the background, one at a time (`ViewerState.preview` answers what the viewer will ask for on that page); navigating or zooming cancels this. `ProjectViewer` creates one source per open project and closes it when the viewer goes away. The page field takes the focus with its content selected when `ViewerState.pageFieldRequests` changes (`focusPageField`, Ctrl+G); Enter goes to the page (a wrong number is undone and the field keeps the focus), Escape gives the focus back to the text.
- `korrektor.pdf`: PDFium for Kotlin (T016, D04). Nothing outside this package touches the native library.
  - `PdfiumLib.kt`: the C functions of PDFium that are used, bound with JNA direct mapping (internal).
  - `Pdfium.kt`: loads and initialises the library on first use, and the one lock every call runs under. Also `PdfException`, the error with a message for the user.
  - `PdfDocument.kt`: an open PDF (`PdfDocument.open(path)`): page count, pages. If opening fails, the reason (not a PDF, needs a password, damaged) comes from looking at the file.
  - `PdfPage.kt`: a page: size after rotation, rotation, the visible area (`bounds`), `text()`, `render(width)` to an image of the whole page and `renderRegion(scale, region)` (a `PixelRegion` of x, y, width and height) to an image of a part of it at a scale (only the part is allocated; the scale and the size of the whole page are limited, see the constants in `PdfPage.kt`), and `largestImageDensity()`: the pixels per point of the page's largest picture (the scan), which is the native resolution. Also `PdfRect`.
  - `PdfTextPage.kt`: the characters of a page's text layer with their boxes, as PDFium reports them (`PdfChar`).
  - Documents, pages and text pages close their children; a closed object fails with a clear error instead of crashing the JVM.
- `korrektor.importer`: reading the text of a PDF into the project's page layers (S03). The rules are in [pdf-text-layer.md](pdf-text-layer.md).
  - `WordExtractor.kt`: turns the characters of a page's text layer into words (`RawWord`: text and box in PDF coordinates). `split` works on a plain list of characters, so the rules are tested without a PDF.
  - `PageGeometry.kt`: the visible page (size after rotation) and the conversion of a box from PDF coordinates (origin bottom-left) to the format's (origin top-left, one decimal), for all four rotations and page areas that do not start at 0, 0.
  - `LineBuilder.kt`: groups the words of a page (`PlacedWord`, in the format's coordinates) into lines in reading order and wraps them in the one body region `r1`. A word joins a line if it overlaps the line's latest word vertically by at least half of the smaller height; lines are ordered by the median height of their words. On pages with several columns the rows of the columns are mixed (known limitation until B3/B4).
  - `PdfImport.kt`: `PdfImport.run(project, progress, isCancelled)` imports every page of the project's PDF: sets the page list, then for each page builds the layer (words, geometry, lines) and writes the original layer and the corrected layer (a copy whose lines point to their own ids as `origin`). Synchronous; progress and cancelling are callbacks (the caller runs it in the background, T023). A page the import cannot get text from (no text, or unreadable) does not stop it: it becomes an empty page with a note (`PageLayer.note`), and the result lists those pages.
- `korrektor.format`: the project format (S01), with no UI and no PDF code. The specification is [project-format.md](project-format.md).
  - `Model.kt`: the data model of a page layer: `PageLayer` → `Region` → `Line` → `Word`, with `Box` and `RegionType`. Original OCR and corrected text use the same types. Unknown fields are kept in `extra`. It also holds `Metadata` (title, author, year, source as typed).
  - `AtomicFile.kt`: crash-safe replacement of a file (temp file, flush, atomic rename) and cleanup of leftover temp files. Every file the project writes goes through it, except the append-only history.
  - `CanonicalJson.kt`: the shared writing rules (separators, key order, number format, string escapes) and parsing with `FormatException`.
  - `IoErrors.kt`: `IOException.reason()`, a readable reason for messages (the text of a file system exception is often only the path).
  - `PageCodec.kt`: reads and writes a `PageLayer` as the text of a page file, one book line per file line. It only delegates to `PageEncoder.kt` (writing), `PageDecoder.kt` (reading) and `PageJson.kt` (typed access to the JSON, with errors that name the place in the file). The split keeps each part small enough for Detekt's size rules.
  - `Project.kt`: a project folder. `Project.create` and `Project.open`, read-only `source.pdf` copy, page files through `PageCodec` and `AtomicFile`; original OCR layers are written once.
  - `FolderTree.kt`: `deleteTree`, which deletes a folder with everything in it (read-only files too) and throws a `FormatException` if something is left, so that cleaning up after a failed or cancelled creation never claims more than it did. `Project.setPages` sets the page list once (the import does); `PageLayer.note` is the optional message of the import on a page (`Model.kt`).
  - `ProjectFile.kt`: the text of `project.json` (format marker, version, page list, unknown fields kept): encoding and validated decoding.
  - `HistoryLog.kt`: the append-only undo history of one page (JSON Lines), read from the end, tolerant of a torn last line.
