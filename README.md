# korrektor

A desktop app (later also for tablets) that turns historical PDFs into clean, searchable text by correcting their OCR.

This is a hobby project in early development.

## Using korrektor
Start the app from the project folder with `./gradlew run`. Features arrive with the stories in the [backlog](backlog/overview.md).

- **Create a project:** click "New project…", choose a PDF, and check the title (it is suggested from the file name). Author, year and source are optional free text, for example `ca. 1790`. The project folder is created next to the PDF unless you change the location. Creating copies the PDF into the project and then imports its text page by page: a progress bar shows "Importing page n of N", and "Cancel" stops it and deletes the new project again, leaving the folder as it was. When it is done the project opens; if the PDF had pages without text (or pages that could not be read), a notice says which, and you can dismiss it. The window cannot be closed while a project is being made.
- **Edit the metadata:** with a project open, click "Edit metadata…", change title, author, year or source, and click "Save". The window title follows. The title cannot be blank. The project folder keeps its name.
- **Open a project:** click "Open project…" and choose the project folder (the folder that ends in `.korrektur`). The window title then shows the project's title. The window shows the scan on the left and the text of the same page on the right, one row per line, with a divider that you can drag; the app remembers where you put it. You can click into any line and correct its text. **Enter** splits a line at the cursor, **Backspace** at the start of a line joins it with the line above, **Delete** at the end joins the line below into it; "Add line" and "Delete line" above the text do the same for the active line. The line with the cursor is marked on the scan by a yellow box, and clicking a line on the scan puts the cursor into that line of the text (dragging still moves the page). When you move the cursor to another line, the scan follows if that line is out of view (useful when you are zoomed in). A dot next to the line number means that the line has no place on the scan (an added line, or the second half of a split word), so it is not highlighted there. **Corrections are saved by themselves:** a second after you stop typing, at the latest every ten seconds while you keep typing, and when you go to another page; there is no save step. A small indicator above the text says "Saved", "Saving…" or "Not saved". Only the pages you changed are written, into the project folder; the original PDF and the original OCR text are never changed. If saving fails (disk full, folder gone, no permission) a red banner says why; your changes stay in the app and saving is tried again every few seconds. Closing the window saves first, without asking; if that fails the app stays open and a dialog offers to save the project to another location (a copy of the whole project, which is then open), to close without saving, or to keep the app open. Opening another project saves the open one first. Ctrl+S is not needed and does nothing. A project can be open in one window only: opening it a second time (in another window or another instance of the app) is refused with a message; a project left open by a crash can be opened again at once. The scan is shown one page at a time: previous and next page, a field to go to a page, zoom (fit width, fit page, steps up to 3200 %, Ctrl+mouse wheel; one step is the scan's own resolution, where one scan pixel is one screen pixel), dragging, scrollbars and the mouse wheel to move the page. The "Word boxes" button draws a box around every word and a stronger one around every line of the current page over the scan, to see what the original OCR found (off at the start, not remembered). The app remembers the page and the zoom of each project in its settings file (`%APPDATA%\korrektor\settings.json` on Windows) and comes back to them when the project is opened again; the project folder itself is not changed. If the folder is not a project, an error is shown and nothing changes; dismiss it with "Dismiss".
- **Export the text:** with a project open, **Ctrl+E**, *File ▸ Export…* or the "Export…" button opens the export dialog. Choose *Plain text* (`.txt`) or *Markdown* (`.md`) and the pages (the whole book at first; leave out the notice page that Google Books adds at the front by starting at page 2). The text of the corrected layer is exported exactly as stored (nothing is normalized, so `ſ` stays `ſ`, and hyphens at the end of a line stay), with these options: *Page markers* write `[Page 12]` (the page number in the PDF) before each page, *Header* writes the title, author, year and source at the top (in Markdown the title becomes a heading), and *Keep the printed line breaks* keeps every line as a line of its own (in Markdown each line ends with a `\`, a hard break); without it the lines of a page are joined with spaces and the pages are separated by a blank line. For plain text all three are on at first, for Markdown all three are off; the dialog remembers your last choices for each format. In Markdown everything that Markdown would read as markup is escaped, so a line that starts with `1.` stays a line and `*` or `_` do not make italics. If some pages in the range are still unchecked, the dialog says how many; they are exported too. Click "Export…" in the dialog, choose the file, and the text is written in the background (a progress bar, and *Cancel* stops it, leaving any old file as it was): UTF-8 without BOM, LF line endings, written so that a crash never leaves half a file. Exporting changes nothing in the project.
- **Keyboard:** you can work without the mouse. **F1** shows this list in the app, and the menus *File*, *Edit*, *Go*, *Page* and *View* show the same keys.
  - Undo and redo: **Ctrl+Z** takes back the last change, **Ctrl+Y** (or **Ctrl+Shift+Z**) brings it back. There is one history for the whole book: if the last change was on another page, that page opens and the cursor is where the change was. A step is a run of typing (a new word, or a pause of a second, starts the next one), a split, a join, an added or a deleted line. After a new change the steps you took back are gone. The history is kept in the project (`history/book.jsonl`, saved together with the corrections), so undo and redo work after the project was closed and opened again, and after a crash; opening a project reads only the end of the history, so it stays fast however long it is.
  - Page status: every page is *unchecked* or *corrected*; the page shown says which, next to "Page n of N", and above the panels the progress is shown, for example "57 of 165 corrected (35 %)". **Ctrl+Enter** marks the page as corrected and opens the next one, **Ctrl+Shift+Enter** marks it as unchecked; the button above the panels (and the *Page* menu) does the same and stays on the page. **Ctrl+Shift+Down** and **Ctrl+Shift+Up** open the next and the previous page that is still unchecked (nothing happens if there is none; the menu entry is grey then). Editing a corrected page does not change its status. A change of status is a step of the history too, so Ctrl+Z takes it back, and it is saved with the corrections; the statuses are stored in `project.json`.
  - Find: **Ctrl+F** opens the search panel above the scan and the text (**Ctrl+H** opens it with the replace field; the ▸ button in the panel shows and hides that field). Type the text to find it on the page shown or in the whole book (*This page* / *Whole book*); *Match case*, *Whole words* and *Regex* are off by default. Only the corrected text is searched, exactly as stored: `s` does not find `ſ` (use the regex `[sſ]`), and a hit is always within one line. A plain search ignores the case of any letter (`ä` finds `Ä`, but never `s` for `ſ`); a regex ignores the case of ASCII letters only (write `[äÄ]`). The results show the page, the line and the text around the hit; a click opens that place, with the cursor on the hit and the line marked on the scan. Searching the whole book runs in the background: results appear as they are found, and *Cancel* stops it. **Enter** in the search field (or **F3**) goes to the next hit and **Shift+Enter** (or **Shift+F3**) to the previous one, wrapping around at the end of the list; the keyboard stays where it was (in the search field after Enter, in the text after F3). With the replace field shown, the list of results is the preview: each hit appears as the line as it is → the line as it will be, with a checkbox (none checked at first; *Select all* and *Select none* are next to the count; **Ctrl+M** checks or unchecks the hit you are on). Nothing changes in the book until you confirm: *Replace selected* changes all checked hits on all pages as one step of the undo history (one **Ctrl+Z** takes all of it back) and the pages are saved like any correction; hits that you left unchecked stay in the list. **Ctrl+R** is the *Replace* button and **Ctrl+Shift+R** is *Replace selected*. **Ctrl+F** in replace mode goes back to searching (the replace field is hidden, nothing is cleared). *Replace* changes the hit you last went to (a step of its own) and goes on to the next one, *Skip* goes on without changing. A hit whose line you changed since the search is not replaced (the panel says how many). The status of a page does not change when its text is replaced. In a regex search `$1` and `${name}` in the replacement refer to groups; otherwise the replacement is taken as typed. **Escape** in the search field closes the panel; the search text and the results are kept for the next time.
  - Lines: **Up** and **Down** move to the line above and below (the cursor keeps its column; on the first or last line of a page they open the previous or next page), **Ctrl+Home** and **Ctrl+End** go to the first and last line of the page. The yellow box on the scan follows.
  - Pages: **Ctrl+Down** and **Ctrl+Up** open the next and previous page (the cursor is in its first line), **Ctrl+G** goes to the page number field (type a number, **Enter** opens it, **Escape** goes back to the text).
  - Editing a line: **Enter** splits the line at the cursor (at the end of a line it adds an empty line), **Backspace** at the start joins the line with the one above (on an empty line it deletes it), **Delete** at the end joins the line below into it.
  - Zoom: **Ctrl+Plus** (also **Ctrl+=**) and **Ctrl+Minus**, **Ctrl+0** for the whole page, **Ctrl+1** for the page width.
  - The shortcuts are not changeable yet. On macOS the page shortcuts will use another modifier, because the system uses Ctrl+Up and Ctrl+Down.

## Development
Requires JDK 21 and network access for the first build, which downloads PDFium (about 4 MB, checked against a pinned checksum) into `build/pdfium`. From the project folder:

- `./gradlew run` starts the app.
- `./gradlew build` compiles, runs the tests and checks formatting and lint (ktlint) and complexity and code smells (Detekt). Any finding fails the build.
- `./gradlew ktlintFormat` fixes formatting problems.
- `./gradlew koverXmlReport` writes a coverage report to `build/reports/kover/report.xml` (report only, nothing fails on it). The Detekt reports are in `build/reports/detekt/`.
